# 01 产品总览（Product Overview）

> Mofa Studio / 魔法工作室 —— 本地优先的创作者一站式 AI 创作工作站

---

## 1. 定位宣言

**用 Agent，而不是建 Agent。**

Mofa Studio 面向创作者终端用户，不做开发者 POC 工具。一句话概括：

> 给创作者一个开箱即用、可深度编排、数据不出本机的桌面 AI 创作中枢。

### 三合一价值主张

| 形态 | 对标 | 一句话 |
|------|------|--------|
| 聊天即创作 | 豆包 | 对话入口直接完成问答、识图、生图、生视频、写作 |
| 任务即交付 | WorkBuddy | 一句话任务 → 自动规划执行 → 交付文档/PPT/成片，含评审环节 |
| 工作流即产线 | ComfyUI | 节点式可视化管线，批量生产图文视频内容 |

### 差异化壁垒

1. **本地优先 BYOK**：密钥自持、数据不出本机、无订阅付费墙——对标产品均为云托管模式
2. **三层工作台纵深**：助理→项目→自动化的用户成熟度路径，越用越深、越用越离不开
3. **资产飞轮**：Skills、SOP、连接器配置、灵感案例四类资产沉淀，切换成本随使用时长上升

### 战略三问应答

| 问题 | 应答 |
|------|------|
| 用户用 100 天后有什么带不走的？ | 打磨好的 Skills、跑通的 SOP 模板、配置好的连接器、发布的灵感案例 |
| 有没有用得更深的路径？ | 助理试用 → 项目依赖 → 自动化托管，每层嵌入更深、沉淀更多 |
| 做工具还是做工作方式？ | 做工作方式：AI 能力被编排进创作者的内容产线，而非孤立工具调用 |

> 商业化脚注：本期不设付费墙与积分体系；定价相关接口不进入 UI 契约，远期仅做可选云增值服务预留。

## 2. 目标用户画像

主定位**创作者**，兼顾轻办公人群：

### P1 自媒体图文创作者（核心）
- 平台：小红书 / 公众号 / 知乎
- 痛点：封面图产出慢、选题枯竭、一稿多发要逐平台改尺寸
- 关键功能：图像生成+多尺寸适配、AI 写作、深入研究、灵感做同款

### P2 短视频创作者（核心）
- 平台：抖音 / B站 / 视频号
- 痛点：脚本→分镜→素材链路割裂、视频格式转码繁琐
- 关键功能：对话内生视频、播客工坊、视频转 GIF/转码、工作流批量出片

### P3 设计师/插画师（核心）
- 痛点：需要精细控制生成过程（LoRA、重绘、放大）、客户反复改稿
- 关键功能：创作工作流节点画布、局部重绘蒙版、参数回溯复现

### P4 轻办公人群（次要）
- 场景：周报、会议纪要、PPT 汇报
- 关键功能：录音转写、PPT/AI 表格生成、自动化日报流水线

## 4. 全局信息架构（IA）

三模式为一级主线，能力面挂载其后：

```
一级导航
├── 助理      ← 默认首页：多模态对话 + 13 个工具能力面板唤起 + 灵感信息流
│               对话中一键「转为项目」进入项目模式
├── 项目      ← 立项 → 自动规划 → 单Agent执行 → 专家评审团 → 验收交付
├── 自动化    ← 流水线编排 + 定时/触发器 + 结果推送（复用 Scheduler）
├── 创作      ← 创作工坊直达：16 个工具的独立工作区 + 作品画廊
├── 工作流    ← FLOW 节点画布（可从助理/项目跳转）
├── 资产      ← 技能市场 / SOP 库 / 灵感广场 / 知识库 / 连接器 / 记忆 / 素材索引
└── 专家模式  ← 存量 B 端模块整体收纳（开关切换，默认隐藏）
```

原则：**能力双入口、单实例**——任一工具既可在助理中作为面板唤起，也可从「创作」直达，共享同一路由与状态。

## 5. 三模式与用户成熟度漏斗

```
        ┌─────────┐      ┌─────────┐      ┌──────────┐
信任度   │ 助理模式 │ ───▶ │ 项目模式 │ ───▶ │ 自动化模式 │
        │ 试用     │      │ 依赖     │      │ 托管      │
        └─────────┘      └─────────┘      └──────────┘
         一句话一事        立项到交付        无人值守流水线
         即时反馈          阶段产物+评审     定时推送结果
              ▲                ▲                 ▲
              └── 每层沉淀更多资产：Skills / SOP / 连接器 / 灵感 ──┘
```

设计约束：
- 导航与 onboarding 按漏斗顺序引导，不强迫升级
- 「转为项目」「存为 SOP」等动作在恰当时机轻量提示，不打断心流

## 6. 资产飞轮（护城河）

```
 使用行为 ──▶ 资产沉淀 ──▶ 产品更好用 ──▶ 更多使用
              │
              ├─ Skills：打磨好的技能包，市场复用
              ├─ SOP：项目跑通后一键沉淀为流程模板
              ├─ 连接器配置：OAuth 凭证与工具绑定持久化
              └─ 灵感案例：Prompt+Skill+Expert 全套配置发布分享
```

闭环路径：项目跑通 → SOP 沉淀 → 一键转自动化流水线 → 发布为灵感案例 → 他用户「做同款」→ UGC 生态起点。

|----------|----------|

## 8. 渐进式披露 Onboarding

用户成长路径即功能解锁顺序（详细需求见 ONBOARD 组）：

```
灵感抄同款 → 不满足改 Skill → 缺数据配 Connector → 分析不够专业找 Expert → 复杂任务上专家团
```

- 空状态、引导文案、推荐流均按此序列设计
- 用户无需预先学习任何概念，第一个成果来自「做同款」

## 9. 场景故事

### 故事 A · 小红书博主的一天
早上打开助理，从灵感广场做同款一份「好物测评图文」模板，替换自己的产品图，10 分钟出 4 张不同比例封面（TOOL-04 多尺寸适配）。下午把爆款文案结构存为个人风格库（TOOL-06），周末设置一条自动化流水线每天早 8 点生成行业热点简报推送到微信（TASK-05）。

### 故事 B · 短视频团队的项目
编导在助理里描述新片创意后点击「转为项目」。系统立项并规划五步：脚本→分镜图→视频片段→配音→合成。单 Agent 保持上下文一致完成脚本与分镜；工作流画布批量渲染分镜；进入评审环节后合规/技术/叙事三个专家并行审查提出 12 条问题，修复阻塞项后验收交付，全流程沉淀为团队 SOP。

### 故事 C · 插画师的精修管线
画师在创作页生成底稿，Konva 蒙版圈选手部重绘三次对比择优（参数快照可回溯）；随后把整套「底稿→重绘→放大→换背景」搭成工作流模板，客户改需求时只改输入节点增量执行，未变更节点命中缓存秒级出图。

## 10. Onboarding 需求组（ONBOARD）

### ONBOARD-01 首次启动欢迎页
- 用户故事：作为新用户，我打开应用立刻明白这是什么、对我有什么用。
- 功能描述：三屏以内讲清三合一价值（对话/任务/工作流各一屏），支持跳过。
- 交互要点：动效演示代替文字堆砌；底部常驻「跳过」。
- 优先级：P0
- 验收标准：新用户 30 秒内可到达 Key 配置或灵感广场。

### ONBOARD-02 Key 配置向导
- 用户故事：作为没有 API Key 的新用户，我能被引导完成第一个 Key 的申请与配置。
- 功能描述：选择厂商（推荐国内可达厂商优先）→ 官方申请页深链 → 粘贴 Key → 连通测试 → 成功动效。支持跳过（游客模式浏览灵感）。
- 交互要点：粘贴即校验；失败给出具体原因（无效/欠费/网络）；密钥即刻入钥匙串，界面不留明文。
- 现有代码映射：`src/services/provider/providerConfigs.ts`（130+ 厂商目录复用）。
- 优先级：P0
- 验收标准：持有 Key 的用户 3 分钟内完成配置并通过连通测试。

### ONBOARD-03 首任务引导
- 用户故事：作为完成配置的新用户，我希望 5 分钟内拿到第一个成果。
- 功能描述：默认展示灵感广场「做同款」推荐位（3–5 个轻量案例：写小红书文案/生成头像/压缩图片），一键复刻。
- 交互要点：成果即时可见；完成后弹出「存为模板/继续探索」二选一。
- 优先级：P0
- 验收标准：见 08 里程碑量化指标——安装到首次成功产出 ≤10 分钟。

### ONBOARD-04 渐进披露机制
- 用户故事：作为进阶用户，我在需要时才遇到更高阶概念。
- 功能描述：按「灵感→Skill→连接器→专家→专家团」序列，在用户触碰边界时上下文引导（如导出失败时引导配连接器）。
- 交互要点：引导卡片可永久关闭；不弹窗打断。
- 优先级：P1
- 验收标准：新用户首周内至少触达一次 Skill 或连接器引导且关闭率 <40%。
