# 04 任务工作台（Task Workbench · TASK 域）

> 对标 WorkBuddy 全量能力。本章先立概念体系，再展开三模式与底层引擎。

## 1. 五概念体系（设计基线）

NLP 思维层级模型映射，五概念各司其职、边界清晰：

| 层级 | 概念 | 回答的问题 | 本项目实现 | 工程本质 |
|------|------|-----------|-----------|---------|
| L1 | **连接器** | 能访问什么系统/数据？ | MCP Host + 原生 Connector | API / OAuth / MCP |
| L2–3 | **技能 Skill** | 这件事具体怎么干？ | 自包含 mini-Agent 包 | Workflow / Prompt / Tool Calling |
| L3–5 | **专家 Expert** | 以什么身份什么范式干？ | 人设+方法论+工具链角色卡 | SystemPrompt / 领域知识 / 方法论 |
| L3–5 | **专家团** | 多角色如何共同完成？ | 团长拆解→并行→整合编排 | Multi-Agent Orchestration |
| 全层 | **灵感** | 别人做成什么样了？ | 成品案例市场+做同款 | 配置包分发形态 |

> L6（价值观与最终决策）属于人与组织。Skill 描述「怎么做」，Expert 解决「我是谁」——二者不可互相替代；灵感不是能力而是资产组合的分发形态。

## 2. 三模式规格

### TASK-01 任务创建与上下文
- **用户故事**：一句话下达任务，@文件、粘贴截图、拖拽上传补充上下文。
- **功能描述**：结构化任务卡：目标 / 输入（引用上下文）/ 输出格式预期（Word/Excel/PPT/PDF/Markdown）。
- **交互要点**：`@` 唤起文件与资料选择器；Cmd+V 直接粘贴剪贴板图片。
- **验收**：三类上下文注入均可在执行日志中回放。

### TASK-02 任务列表管理
分组（按项目空间）/ 搜索 / 筛选 / 多任务并行实例（并行的是独立任务，非任务内分工）；运行中任务进度常驻侧栏。P1。

### TASK-03 助理模式
- **定位**：一句话一事，低门槛快响应——用户成熟度第一层（试用）。
- **功能描述**：即 CHAT 域主界面 + 能力面板；可操作授权目录文件、调用已启用连接器。
- **关键动作**：对话卡片上「转为项目」按钮——复杂化时无缝升级。
- **验收**：简单任务（写邮件/查数据/总结文档）平均完成 ≤1min。

### TASK-04 项目模式
- **定位**：立项到交付的完整闭环——第二层（依赖）。
- **流程规格**：
```
立项(目标+输入+输出格式) → 自动规划步骤(计划可编辑) → 单Agent逐步推进
  → [可选]专家团协作(TASK-15) → 评审环节(自动拉起评审团 TASK-16)
  → 阻塞项修复闭环 → 验收交付 → 产物入产物中心 → 提示SOP沉淀
```
- **交互要点**：进度看板展示阶段与产物；计划步骤支持人工增删改；每步产物即时预览。
- **验收**：PRD 类项目全程无人工干预走完规划→创作→评审；中断后可从断点续跑。

### TASK-05 自动化模式
- **定位**：固定流水线无人值守——第三层（托管）。
- **功能描述**：触发器=定时(cron)/手动；流水线=SOP 绑定参数化输入；结果推送（桌面通知 v1，IM 连接器 M4）；失败告警与重试策略。
- **代码映射**：复用 `src/pages/scheduler/`（cron 编辑器/执行记录/worker 模型）扩展。
- **后台支撑**：托盘常驻进程 + SQLite 队列断点续跑（对标其"云端 7×24 托管"的本地等价）。
- **验收**：关窗后流水线照常执行；系统重启后 autostart 恢复队列。

## 3. 路由引擎（分版本交付）

### TASK-06 路由 v1（M1）
意图分类（规则+小模型）→ 能力面板预选（勾选本次可用工具集默认值）。服务助理模式基础体验。P0。

### TASK-07 路由 v2 完整四层（M3）
```
① 意图分类 ──▶ ② Skill 检索调度 ──▶ ③ Skill 内子路由 ──▶ ④ 沙箱执行
   规则+LLM      description向量+关键词        Skill自带的       授权白名单内
   复合分类      混合匹配 TopK                 执行逻辑          工具调用
```
- 核心机制：新 Skill 上架**零路由代码改动**——manifest.description 声明式注册意图（"SEO 式"匹配）。
- 执行策略决策流程（伪代码）：

```
route(task):
  intent = classify(task)                    # LLM 分类
  complexity = estimate(intent, context_size, deliverables)
  strategy = if project_mode:      SINGLE_AGENT_CREATION
             elif intent.multi_domain and complexity.high:
                                      EXPERT_TEAM
             else:                    SINGLE_AGENT_CREATION
  plan = planner(strategy, task)             # 强模型规划
  for step in plan:                          # 快模型执行
     skill = skill_router(step)              # 向量+关键词混合检索
     result = skill.execute(step, sandbox)   # 白名单沙箱
  if project_mode: review = review_panel(result)   # 评审钩子
  return deliver(review or result)
```

### TASK-08 执行策略三分法
| 策略 | 适用 | 决策方 |
|------|------|--------|
| 单 Agent 直执行 | 创作类任务，保上下文一致性 | 默认 |
| 专家团协作 | 天然多领域交付（业务+技术+实施类） | 路由判断或用户指定 |
| 评审团校验 | 项目模式验收环节 | 自动触发 |

> 约束：创作阶段禁止中途分角色拼接内容；多 Agent 价值在交叉校验而非分工写作。

## 4. 连接器（Connector）

### TASK-09 连接器安装与管理
- **安装三步**（对用户呈现为"一键添加+扫码"）：① 装载接口依赖与插件 ② OAuth 授权弹窗 ③ 工具描述注册进网关。
- **功能描述**：官方连接器目录 v1（网盘/邮箱/日历/文档类 BYOK 可达服务）+ 自定义连接器（MCP server 配置）；凭证持久化入钥匙串；授权范围可视化与撤销。
- **验收**：安装到首次成功调用 ≤2min；撤销授权后工具立即失效。

### TASK-10 任务级工具作用域（注意力稀释防护）
- 对话/任务创建时勾选本次可用工具集；默认由路由 v1 按意图预选。
- 原理：工具描述拼入 system prompt，全量注入导致选错工具与注意力稀释。
- 附带：MCP 工具动态上下线时勾选列表自动刷新。

### TASK-11 同质工具冲突消歧
多工具声明同一能力时（如两个都能建会议）：用户历史偏好 > 显式询问 > 默认标记并记录。P2。

## 5. 技能（Skill）

### TASK-12 Skill 规范与 manifest
- **定位**：Skill = 可复用任务能力包，自包含 mini-Agent——自带路由规则、工具清单、执行逻辑。
- **manifest 结构**：
```yaml
name: meeting-review
description: "整理会议录音，输出纪要与待办清单"   # 声明式意图注册(路由匹配依据)
connector_deps: [calendar, docs]                # 连接器依赖声明
tools: [asr, file_write]
steps:                                          # SOP 步骤或脚本引用
  - find_this_week_meetings
  - create_summary_doc
  - ...
input_schema: { audio_dir: dir, output: doc }
```
- **兼容性**：支持 OpenClaw 社区技能包导入转换。
- **验收**：按 manifest 导入的 Skill 无需任何核心代码改动即可被路由 v2 匹配执行。

### TASK-13 Skill 市场
查找安装 / 上传本地技能包 / 自然语言创建自定义技能（描述需求自动生成 manifest 草稿）/ 启用停用与搜索。
代码映射：复用 `src/pages/management/skills/` 与 SkillHub（发布/审核/命名空间/标签/评分）基础设施。P1。

## 6. 专家与专家团

### TASK-14 专家体系
- **定位**：专家=角色卡（人设+方法论+工具链绑定），解决"以什么身份什么视角处理"。
- **功能描述**：专家卡片浏览（行业分类）；召唤进对话；我的专家创建；分享导出。
- 代码映射：`src/pages/management/agents/` 改造消费化。P1。

### TASK-15 专家团编排（Rust 自研）
- **定位**：复杂多领域任务的多角色协作机制——团长理解目标→拆解→并行分派→整合交付。
- **实现约束**：借鉴 AgentScope 消息传递/Pipeline 抽象，tokio 实现，SQLite 事件溯源持久化；拒绝 Python sidecar（评估记录见 09 §5）。
- **验收**：三专家并行任务汇总无消息丢失；单专家失败可重试不影响其余。
- 排期 M3–M4，P2。

### TASK-16 评审工作流（项目模式专属）
- **用户故事**：项目完成后，多个领域专家从不同视角审查成果并列出问题清单。
- **功能描述**：评审维度配置（合规/技术/交互/事实性…）；评审专家角色模板库；并行审查→问题聚合报告（阻塞项/建议项分级）；修复闭环追踪（修复后复审）。
- **设计依据**：实测 WorkBuddy 的真实机制——创作阶段单 Agent，评审阶段才拉起多 Agent；多 Agent 价值在交叉校验盲区。
- **验收**：54 问题级聚合报告渲染流畅；阻塞项全部闭环才允许标记交付完成。

## 7. 产物、文件与记忆

### TASK-17 产物中心
- **用户故事**：所有任务交付物在一个地方统一查看、预览、分享。
- **功能描述**：产物类型：文档(MD/Word)/表格(xlsx/csv)/PPT/PDF/媒体文件；右侧结果区四视图：产物列表 / 全部文件树 / **变更 diff** / 预览（Word·Excel·PPT 用 Univer 渲染，可直接二次编辑）。
- **验收**：产物点击即预览无需下载；diff 视图能定位两次执行间的文件差异。

### TASK-18 本地文件操作
授权目录白名单制：任务发起时显式选择可访问目录；批量整理/重命名/转格式；所有写操作留审计日志（专家模式可查）。对标其双权限模式的「本机模式」。P1。

### TASK-19 记忆系统
- **功能描述**：sqlite-vec 向量化长期记忆——用户偏好、项目上下文、历史决策；对话/任务中自动检索注入。
- **隐私四权能（硬性要求）**：可见（记忆条目列表）/ 可编辑 / 可删除 / 总开关一键停用。缺失任一项不得上线（07 隐私章节联动）。P1。

## 8. SOP 与灵感（资产飞轮）

### TASK-20 SOP 一键沉淀
项目跑通后提示「存为 SOP」：步骤序列+所用 Skill+专家配置打包为模板；模板可直接「转自动化流水线」（绑定触发器即成 TASK-05 任务）。三模式闭环的关键铰链。P1。

### TASK-21 灵感广场
- **定位**：成品案例市场——不是提供能力，是提供「别人已经做出来的结果」；新用户零学习成本入口。
- **功能描述**：
  - 案例卡片=场景成果展示 + 背后完整配置包（Prompt+Skill+Expert 绑定关系）
  - **做同款**：加载全套配置→替换素材→产出自己的版本
  - **缺依赖检测引导**：案例绑定的 Connector/Skill 未安装时，提示并一键安装（复刻 ComfyUI 缺模型检测模式）
  - 收藏 / 分享 / UGC 发布（走 SkillHub 审核流）
- **IA 落位**：助理首页灵感信息流（发现入口）+ 资产导航独立广场页。
- **验收**：做同款到产出首个成果 ≤5min；缺依赖案例引导安装成功率 ≥80%。

## 9. 其他

### TASK-22 MCP Host
rmcp 官方 SDK 实现客户端；MCP server 配置管理并入连接器体系；工具经沙箱代理调用。P1。

### TASK-23 IM 连接器
企业微信/飞书官方 API 优先；个人微信协议方案标注合规风险仅作技术储备不排期。自动化结果推送依赖此能力。P2 / M4。

### TASK-24 项目空间
任务分组容器；空间内沉淀的专家/Skill/连接器配置一键复用到新任务。P2。
